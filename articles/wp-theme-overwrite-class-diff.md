## 結論

静的HTMLで作ったページを、すでに動いているWordPressテーマへ上書きするときは、**文言（テキストノード）の差分だけでは足りません**。`class` 属性の差分も取ってください。

CSSに定義が残っているクラスは、HTML側から消えても**エラーも警告も出ません**。そして「画像の読み込み件数」「セクションのY座標」「ページ総高」「コンソールエラー0件」といった、よくある反映後チェックのすべてをすり抜けます。私はこれで、テーマが持っていた装飾アニメーションをまとめて消したまま公開しました。

## どういう構成で起きるか

次の3つがそろうと起きます。

1. 静的HTMLをWordPress化したテーマがあり、クラス名と構造が1対1で対応している
2. テーマ側だけに後から修正が入っている（＝静的HTMLが古い、あるいはその逆）
3. アニメーションや装飾の指定が、**CSS側に定義を置き、HTML側はクラスを付けるだけ**で成り立っている

この状態で静的HTML側を正としてテンプレートへ上書きすると、テーマ側にしか無いクラスが消えます。CSSの `@keyframes` と定義は残るので、構文エラーにはなりません。

- クラスが無い → ルールが当たらない → 何も起きない
- CSSの構文としては正しい → エラーも警告も出ない

さらに、スクロールで出てくる系のアニメーションは「最終状態＝静止状態」で位置と大きさが決まる作りが多く、**セクションのY座標も総高も変わりません**。寸法で突き合わせる検証とは、原理的に相性が悪いわけです。

私の場合、反映後に次をすべて確認して「問題なし」と判断していました。

- 画像がすべて読み込み成功、読み込み失敗0件
- 各セクションのY座標とページ総高が、ローカルと公開版で一致
- コンソールのエラー・警告0件
- 横スクロール0px（複数の画面幅で実測）

それでも、スクロールで要素が出てくる動きと、装飾が揺れる動きがまるごと消えていました。**測っていた軸が「寸法」だけだった**のが原因です。

## 対処：クラス名の差分を取る

上書き前に、旧ファイルと新ファイルからクラス名の集合を抜いて比較します。

```bash
for f in old.php new.html; do
  grep -oE 'class="[^"]*"' "$f" \
    | sed -E 's/^class="//; s/"$//' \
    | tr ' ' '\n' \
    | grep -v '^$' \
    | sort -u > "/tmp/$(basename "$f").cls"
done

# 旧ファイルにしか無いクラス = 上書きで消えるもの
comm -23 /tmp/old.php.cls /tmp/new.html.cls
```

ここが空でなければ、**1件ずつ見て「意図した削除か」を判断します**。空でないまま進めてよいのは、自分でそのクラスを捨てたと説明できるときだけです。

私は旧ファイルから「クラス名 → アニメーション名」の対応を抜き出し、静的版に付け直しました。復元後は、件数と種類の両方を旧版と突き合わせています。

### この抜き出し方の限界（手元で確認済み）

PHPテンプレートに対して上のコマンドを使うと、次の2つで足りません。実際に試した結果です。

```php
<section class="sec anim-fade">
  <div class="<?php echo $modifier; ?> anim-float">動的に組まれるクラス</div>
</section>
<script>document.querySelector('.sec').classList.add('anim-js-added');</script>
```

このファイルから抜き出すと、クラス名として `<?php` `echo` `$modifier;` `?>` が混ざって出てきます。**動的なクラス名が「拾えない」のではなく、PHPの断片がクラス名として紛れ込みます。** そして `classList.add()` で後から付くクラス（ここでは `anim-js-added`）は、HTMLのどこにも書かれていないので最初から出てきません。

対処は2つです。

- **レンダリング後のHTMLで比べる**。`curl` で公開URLのHTMLを取れば、PHPは展開済みです
- **JSが付けるクラスは別に探す**。`classList.add` と `className` を grep して一覧にする

## 確認方法：動いている本数を数える

「クラスが付いた」ではなく「アニメーションが走っている」を数えます。

```js
// 走っているアニメーションの本数（擬似要素のぶんも含む）
console.log(document.getAnimations().length);

// 内訳を見る
console.log(
  document.getAnimations().map((a) => ({
    target: a.effect?.target,
    pseudo: a.effect?.pseudoElement, // '::before' など
    name: a.animationName,
  })),
);
```

復元前の本数を控えておくと、次回以降はこの1行で比較できます。

### getComputedStyle では擬似要素を数えられない（手元で確認済み）

本体にはアニメーションを当てず、`::before` にだけ当てた要素を作って測ったところ、Chromium では次のようになりました。

| 取得の仕方 | 返り値 |
|---|---|
| `getComputedStyle(el).animationName` | `none` |
| `getComputedStyle(el, '::before').animationName` | `float` |
| `document.getAnimations()` | 擬似要素のぶんも含めて取得できる（`pseudoElement: '::before'`） |

つまり、`getComputedStyle(el).animationName === 'none'` で「死んでいる要素」を数える方法は、**装飾を擬似要素で作っている場合に見逃します**。擬似要素を第2引数で指定するか、`document.getAnimations()` で数えるのが確実です。

:::message
要確認：上の表は Chromium で測った結果です。Firefox / Safari でも同じかは確かめていません。
:::

## 上書き前に見る3点

同じ事故を避けるため、手順をこの順に固定しました。

1. **そのURLが何を返しているか調べる。** 反映先が静的ファイルの置き場とは限りません。`curl` で `<meta name="generator">` と `<title>` を見て、WordPressなのか素のHTMLなのかを先に確定させます
2. **テキストノードの差分を取る。** 旧テンプレートにしか無い文言は、上書きで失う文言です
3. **class属性の差分を取る。** ここが私の手順に無かった項目です

加えて、生成したPHPは本番ディレクトリに置く前に `php -l` で構文チェックを通し、差し替え前にテーマ一式のバックアップを取っています。

## まとめ

- 静的HTMLを既存テーマへ反映するときは、**文言とクラス名の両方**を差分で見る
- CSSに定義が残っているクラスの欠落は、エラーが出ず、寸法の検証も通る
- 検証項目は「見た目の寸法」だけでなく「**機能が生きている本数**」を数える形にする
- クラス名の抜き出しは、PHPの断片が混ざる・JSで付くクラスを拾えないことを前提にする

WordPressの独自テーマ開発は5年ほど、50件ほど担当してきましたが、「静的版をWordPress化したものへ、静的版から差し戻す」という方向の作業は経験が少なく、チェック項目が育っていませんでした。検証がすべて緑でも、**測っていない軸があれば壊れている**という当たり前の話でした。
